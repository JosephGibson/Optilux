## 1. Goal and exit
- Goal: the repository, the harness skeleton with its tests and doc checks, the hooks, `optilux status` with its skill and agents, and a release path that ships a placeholder pack from a merged PR.
- Exit (roadmap.md#m0-foundation): every M0 verb runs with its tests green; the hooks refuse a bad commit message and a forbidden git command; `optilux status` prints the next stored prompt; CI green on the m0 push and on the PR; the PR `0.00: Foundation.` rebase-merged by the user; the release for the newest phase exists with its optilux-<version>.zip; docs/handoff.md written.

## 2. Scope
- In: verbs `test`, `verify docs`, `status`, `milestone start`, `pack build`, `pack release` (design.md#5-interfaces); skills optilux-next and optilux-release; agents researcher and reviewer; git and Claude Code hooks with the permission allow rules; .github/workflows/ci.yml and release.yml; the placeholder pack under shader/; LICENSE; the CHANGELOG 0.00 entry; .gitattributes; pyproject.toml, uv.lock, ruff; AGENTS.md Layout updated as directories appear.
- Out: install, launch, run, the mod, any game launch, snapshots/ (M1); `verify records`, calibrations (M2); `verify similarity`, the hello pack, offline levels (M3); optilux-plan (roadmap.md#decisions D8); `jvm` (post-1.0). Nothing under runtime/ is read or written.

## 4. Ground rules
- Run from a Claude Code session in C:\Projects\Optilux, on branch m0 after 0.00.00; prompts from docs/prompts/m0.md verbatim; no questions mid-run except the three named stops: the go before the first push (0.00.00), the uv install (0.00.01) and the repository merge settings (0.00.06).
- No game launch; nothing under runtime/ is read or written; no system settings: git config only with `--local`; the uv install under the user's profile on the user's OK (D1).
- Commits under the user's name, no attribution, one per phase, pushed right after (`git push -u origin m0` the first time); never force, never `--no-verify`, never to main.
- Every phase ends test-green: `optilux test`, ruff, and from 0.00.02 `optilux verify docs`. A failing check is fixed inside the phase, never skipped.
- Docs: a phase that changes behaviour a doc describes fixes the doc in the same commit (workflow.md#docs-rules); byte caps measured after every edit; LF without BOM; AGENTS.md Layout gains each new top-level directory in the phase that creates it.
- Status lines of AGENTS.md and roadmap.md are updated in each phase commit from 0.00.01 on (workflow.md#running-a-milestone); the bootstrap commit carries the docs exactly as Phase 0 left them.
- Stop on a condition of section 7; at every stop overwrite docs/handoff.md and report.

## 7. Stop conditions
Stop, record in docs/handoff.md and report; never work around:
- `gh auth status` fails, a repository named Optilux already exists, or a push is refused;
- `git status` before the bootstrap commit lists anything under runtime/;
- the user declines the uv install (0.00.01 cannot proceed without it: workflow.md#code-conventions);
- a phase's tests cannot be made green within twice its estimate;
- a doc cap would be exceeded and the cut needs a decision;
- CI stays red for a cause outside the repository for more than 30 min;
- anything would need a system setting, elevation or a system-wide install.
