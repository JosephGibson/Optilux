# Run record
Status: draft; the identity contract, the record's fields and the run spec, split from measurement.md on 2026-10-06; measurement rules: measurement.md. As built, 0.01.08 to 0.01.13: optilux/record.py (the spec's checks, the identity, the writer, the tree hash), session.py's status rules and `run` for acceptance runs; M2.P01: the identity built before the launch, with `harness`; M2.P04: the world restored before each session (optilux/world.py); M2.P05: measurement and calibration runs and A8 and A11 on a mode's schedule (optilux/measure.py).

## Record
One JSON per session, failures included, committed under results/records/<name>.json. It is the ledger; there is no hand-written ledger.
- Self-contained: a record carries every number needed to re-judge its verdicts, as per-capture summaries. Frame-level samples and raw artifacts (PNG, npy, PresentMon CSV) go to results/raw/<name>/, ignored and disposable; the budget is ~200 KB per record (frame samples would add ~2.5 MB per session, est.); M1's acceptance records run to 238 KB (m1-acceptance-9 and -10), and M2's `verify records` decides how they count. ALC's tracked cards cited ignored run folders, and those paths went stale.
- kind: measurement | calibration | acceptance. Acceptance runs carry `acceptance: [{item: A1..A12, pass, evidence}]` and no verdicts; calibration runs carry no verdicts.
- status: ok | invalid | failed | aborted, with `reason` beside it. As built: ok only when every item passed; invalid on a `hook.error`, a hook failure in the session's latest.log (one before `hello` sends no event) or an Iris load failing outside `shaders.reload`; failed on any other problem: the request log holds the token or went unchecked, the mod answered a line no request sent, the option files did not read back as written, the quit exited non-zero, the selftest failed at the start, A4's copy was not deleted, F4's table was not completed, an item failed or the session broke; aborted on the user's stop. A session whose launch contradicts the identity built before it records `identity: null`, never with status ok. A measured run (M2.P05): invalid also when a focus.lost or screen.opened ended it (plans/m2.md D42); failed also on a capture without its numbers, PresentMon dying, a variant's options not reading back, the run's files not deleted, or an A8 or A11 entry unjudged (its verdict comes with M2.P07); aborted also when the next run finished it as an orphan (D41): its captures summarized only when its PresentMon ended by a clean stop (the run's journaled one, or its session stopped by the next run), its files under shaderpacks/ the ones its journal names it wrote.
- As built, an acceptance record also holds `spec` (verbatim), `startedAt` and `endedAt` (UTC), `recorded` (below), `variants`, `session` (the world's restore: files copied and deleted, its tree hash; the launch's facts, the mod's checks, every step's answer, the events with the step that was running, the quit, the request log's token check, the option files read back, A4's copy deleted) and `raw`; with `reloads` in the spec, `reloadTable` (F4: heap after GC and private bytes every 10 reloads, the growth per reload, each reload's seconds). A1's inert launch never measures: its facts live in A1's evidence, so the identity is the session launch's.
- As built for a measured run (M2.P05): `spec`, `notes`, `startedAt`, `endedAt`, `identity`, `recorded` (beside M1's: the game's remote connections at the join, F10), `mode`, `calibration` (null before M2.P07, D40), `variants`, `captures` (Fields), `acceptance` for A8 and A11, `heapTable` with `heap` (rows of heap after GC and private bytes at the start and every 10 reloads, the growth per reload, the physical memory), `session` (the restore, D42's check, the twins, the launch and mod facts, the start, the laps, the weather ticks, PresentMon's start, stop and file, the quit, the checks, the steps and events counted, the time split per phase) and `raw`. Raw: presentmon.csv, steps.json, events.json, captures.json (every capture's window marks, reload and timers), requests.jsonl, journal.json (the run's journal, partial.json while it runs).
- Raw (0.01.08): requests.jsonl, session-latest.log, world-manifest.txt (the snapshot's file list), session-threads.txt (A1's control), a2/<view>/ (the capture attempts and the F2 screenshots kept), a1/ (latest.log, threads.txt); 0.01.09: a4/ (the recovery frame), a9/ (presentmon.csv and its log, the capture's capture.json; its PNGs deleted after the match), f4/ (each GC.heap_info).

## Identity
Every input that can move a measurement; matched key by key (AGENTS.md Terms). Calibrations match on it (measurement.md#calibration). Built before the launch from the files the session will use, so a failed launch records it; the launch's jars, resource packs and settings, the config files read again and the Java `hello` reports are then held against it (plans/m2.md M2.P01). One key each, in the record's order (optilux/record.py IDENTITY_KEYS; a test keeps the two equal):
- `platform`: a hash of the platform file's loaded sections (every top-level key but referencePacks and worldPrep, the tiers cut to the session tier's chain, the note keys stripped), plus the mod tier; the whole-file hash is recorded, not matched. The reference pack is a variant's (plans/m2.md D39);
- `launchSpec`: the hash of config/platforms/<id>.launch.json (platform.md#install-and-launch);
- `mods`: sorted sha512 of every jar launch places: the tier's pins and the store's optilux-helper;
- `world`: the snapshot (its path, tree hash: the sha256 of its manifest, one `<sha256>  <path>` line per file sorted by path, and file count); `run` restores the live world, the spec's `world`, to it in place before launching (optilux/world.py, plans/m2.md D44), and refuses a snapshot whose hash moved since the identity was built;
- `views`: the views file's hash (config/views/<world-id>.json);
- `resourcePacks`: the set (standard) and each pinned pack's sha512;
- `settings`: the options.txt keys the harness writes from suite.json display, `--set` overrides applied and listed, and every other key with its value as the game will read the file (plans/m2.md D37), the iris.properties keys but shaderPack, whether the token is passed, and the hash of Sodium's options file. The pack and its options are never identity: they are variant fields (below);
- `suite`: a hash of display, modes (views and rounds per mode), capture, validity and statistics, with note and ALC-context keys (`why`, `*Why`, `status`, `estMinutes*`, `alc*`) stripped, so editing a note or an estimate never forces recalibration while a changed view list or round count does;
- `java`: runtime, version and sha256 of the JDK's release file (the version equal to the one `hello` reports), heap, args (the profile's flags only: `-Doptilux.token` is fresh per launch and the spec's JVM options belong to the launch spec), all checked against the started process;
- `system`: GPU (the primary display's adapter), HAGS as applied (HwSchEnabled in that adapter's D3DKMT WDDM 2.7 caps, only read; a failed query refuses the run, plans/m2.md D38), resolution (the primary display's mode read DPI-aware, D22; refused unless it is suite.json display.resolution, and the session ended at its start unless `state`'s framebuffer equals both, plans/m2.md D38), window mode (from the written options), Windows build number (the update revision is recorded, not matched, like the driver);
- `harness`: the sha256 of every optilux module the measured session imports (read with ast from optilux/verbs/run.py, deferred imports included), and PresentMon's file, sha256 and arguments (plans/m2.md D36). An edit outside that closure (a doc, the CLI's registry, a verb such as status) never forces recalibration; the install verb's module is inside it, as `run` imports its paths.
- Recorded but never matched (`recorded`): options.txt's hash as the game reads it, the graphics driver (assumed good, user 2026-10-05; a run refuses when it cannot be read), the update revision, the display's rate and count, the caps' other bits, the adapter's LUID and HwSchMode (the requested HAGS state), the platform file's hash, AMD's PresentMon (F2), the other JVMs the gate saw, the harness version (HEAD and whether the tree was dirty).

## Fields
- identity (above) and calibration id.
- offline: closures and predictions, each with its method and evidence (offline.md#decision-powers).
- per variant, the variant fields (they may differ between compared runs): pack tree hash + effective option values read back after reload. As built for a zip pack: its sha512 and `shaders.options`' values after the start-of-run reload.
- per capture: view, variant and its role (baseline | candidate | twin), round, sequence index, the summaries (median GPUBusy, median and p95 FrameTime, frame count, halves, PresentMode, per-pass timer medians, dropped timer frames), frame hashes, validity flags. Raw artifacts are referenced by run name and capture index.
  - As built (M2.P05): `index`, `pass` (1 the warm-up pass, 2 the schedule), `view`, `variant`, `role`, `round` (0 in the warm-up pass), `settleS`, `frames` (the mod's), `rows` (the cut's), `edges`, `gpuBusyMs`, `frameTimeMs`, `frameTimeP95Ms`, `gpuLatencyMs`, `gpuBusyOverFrameTime` (median over median), `halvesGpuBusyMs`, `halvesPct`, `presentMode`, `flags`, `valid` (measurement.md#validity); a timers-on capture's `timers` (frames, missing, topLevelMs, each pass's depth and median ms, the dropped counts, residualMs: A11's GPUBusy less the top-level sum, median over the frames).
  - A variant as built: `id`, `role`, `pack` (the file Iris loads), `sha512` (the zip's; a twin's is its source's), `profile`, `options` (as written), `timers`, and `effective`: the options read back after its reload, the baseline's whole map with its sha256, another variant's sha256 and the values that differ from the baseline's.
- verdicts and cost rows (measurement.md#verdicts-and-cost-rows), each with the view set and thresholds it used.

## Comparison
- Comparable = identity equal; only variant fields differ. `compare` refuses otherwise and names the field.
- Declared treatment: an experiment may name one identity field as its treatment (mod presence, JVM runtime and args). `compare` then lets exactly that field differ. Such a field cannot change inside a session, so the experiment uses launch-level bracketing and launch-level null calibration (jvm.md#protocol); the in-session thresholds never judge it.

## Run spec
The input of `run`: name (unique, `[a-z0-9-]{1,40}`; `run` refuses an existing name), kind, mode, views, variants (pack + profile), tier, resource-pack set, treatment (declared-treatment experiments only), notes. As built (0.01.08; reloads 0.01.09), a JSON file with name, kind, views (the views file's id, also the snapshot's), world (the live world folder under game/saves/), variants, tier, resourcePacks, items, notes and reloads (F4's count, a multiple of 10); unknown fields are refused.
- `run` validates it before launching: views exist, variants build, identity matches, a measurement run has a matching calibration, the reload budget holds (measurement.md#session), nothing else holds the GPU (the launch gate refuses a game under runtime/, an optilux- ETW session and a Gradle build; a measured run waits for D42's idle machine); errors name the fix.
- `run <spec> --check [--json]` (M2.P01): the spec's checks and the identity as `run` builds them, the identity printed key by key; nothing launched or written, the live world left to `run`'s restore, and launch's own refusals (its gate, the pinned files' hashes, a saved pack settings file) too.
- As built for acceptance runs: kind acceptance only (no calibration needed), mode and treatment absent or null, the bench tier, the views file valid and its snapshot present, the world present and restored to the snapshot (`world restore`, D44), one variant (the reference pack, profile null: the pack's defaults, `launch` refusing a saved shaderpacks/<pack>.txt), the standard set, items among A1, A2, A3, A4, A7, A9 and A10, the session's reloads (two, A4's two, F4's) within capture.reloadCap, the display equal to the suite's; the launch gate is the GPU check.
- As built for measured runs (M2.P05): `mode` quick or full; kind measurement or calibration, or acceptance with `items` among A8 and A11 (A8: the baseline without timers and a candidate equal to it with them; A11: every variant timed); `calibration` written null (plans/m2.md D40) until M2.P07's `calibrate`; `variants`: objects of `id` ([a-z0-9-], never twin...), `pack` (the reference pack until M2.P08's passthrough), `profile` (a config/profiles/ name or null), `options` (text or booleans over the profile's: "-1", never -1) and `timers`, the baseline first, a calibration run's alone (the runner adds twinsPerSession twins, a measurement run's one A/A twin); `heap` true or false; with heap true a measurement run may set `rounds` and `dimensions` (dimension ids keeping the mode's views there), a budget run's (plans/m2.md M2.P06); a calibration run without timers (timer twins are M4's) or heap reads; no `reloads` or `treatment`; the planned reloads with selftest's within capture.reloadCap; the snapshot's view functions equal to the views file's (`world prep` writes both).
