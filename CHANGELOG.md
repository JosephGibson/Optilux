# Changelog

User-facing changes per release, newest first. Versions are MAJOR.MINOR.PATCH from 0.2.0 on; the first release was v0.00.06.

## 0.4.0 Visual loop
Optilux's first shader pack, a minimal hello pack, and the visual loop around it: frames taken at every bench view are compared bit for bit or by how visible a difference is, checks before any launch catch a build that does not compile or that copies Complementary's code, and the performance calibration is redone on textures held still. The hello pack draws textures, vertex colour and light only; the look arrives in later releases.

## 0.3.0 Perf loop
A performance verdict on a shader change: the harness times calibrated sessions on the bench world's views, restores the world before each run and says whether a change is faster, slower or inside the noise. Still no shader of Optilux's own: these verdicts were tried on Complementary Unbound, and the first pack arrives in a later release.
- `optilux run <spec> --check` validates a run spec and prints the identity the run would record, without launching the game. The identity now also covers the harness code a session runs, PresentMon's build and flags, every Minecraft option the game reads and Windows' GPU scheduling as applied.
- The helper mod times measurement windows itself (`window.measure`): a settle counted from the shader reload's completion inside the game, then a window in seconds on PresentMon's clock, so the harness cuts PresentMon's frames by the window's own stamps instead of sleeping. A reload, a dimension change or leaving the world inside a window fails it. `state` reports the size the game renders at, and `run` ends a session whose size is not the display's.
- The helper mod times each pass of the shader pipeline on the GPU (`timers.start`, `timers.read`, `timers.stop`): Iris marks every pass, the mod stamps each mark with a GPU timestamp and reads the stamps only once the GPU has written them, so the game never waits; a frame whose stamps come in late is dropped and counted. Timing costs about 0.2 % of the GPU's time, inside the noise. But the passes' times did not add up to PresentMon's: on one view (underwater), turning Complementary's shadows off saves GPU work that no timed pass contains. So no cost row uses the timers; they stay in the mod, and a later milestone tries Viewfinder's timers instead.
- `optilux world snapshot <id>` copies a bench world into snapshots/ with a manifest, a tree hash and the bench player's id; `optilux world restore <id>` puts the live world back to its snapshot in place, copying back only what changed and deleting what was added. `run` now restores the world before every session instead of refusing one that moved.
- `optilux world prep <id>` prepares a bench world in one launch: Chunky pre-generates the area around its views, every stray entity is removed but the posed mobs and the End's crystals, one function per view sets its time and weather, a 4K reference frame is kept per view, and the snapshot is retaken. The bench world bench_263 is prepared.
- `optilux run` runs measurement and calibration sessions. A measured run waits until the machine is idle and no other program uses the GPU, keeps the displays from turning off until it ends (with them off nothing is presented to measure; a run started with them off already is refused), launches the game (once, or once per few views when the session is too long for one launch), warms up, then at each view measures the baseline and each candidate, plus an exact copy of the baseline (the A/A twin), in the order baseline, candidate, baseline: each window is timed inside the game and PresentMon's frames are cut by the window's own stamps after the session. Every capture records its GPU time, frame-time tail and frame count and whether it is valid: GPU-bound, presented in exclusive fullscreen, enough frames, steady halves, nothing interrupting the window. A session disturbed at the machine ends as invalid, and a run killed from outside is finished by the next run, which ends its game and writes its record as aborted.
- One game launch now holds at most 20 shader reloads (`capture.reloadCap`, down from 288). On this machine's graphics driver every shader reload leaks about half a gigabyte of graphics memory: after about 21 reloads the card's 16 GB are full and the baseline renders 13 to 474 % slower. Budget runs measured this (`run` with `heap`, which now also reads the GPU memory after every reload) and set the bench heap (6144 MiB, unchanged), the cap and the calibration's size: 2 twins a session, 10 sessions a mode. Sessions over the cap now split into launches of a few views each (full mode: 11 launches of one view, each warming up over its view first), each recorded on its own; a stopped session resumes at its first launch that did not end ok, a launch whose setup changed ends the session, and once every launch is ok the session's own record holds the verdicts over all its views.
- The bench world's eleven views are surveyed, twice: on every view the baseline (Complementary Unbound with the played settings) keeps the graphics card busy for at least 99.7 % of each frame, so its timings measure the shader, not the CPU. A pack that draws almost nothing kept the card busy too, at 1,000 to 2,000 frames a second, so the CPU's own share of a frame sits below about 0.5 to 0.9 ms on every view. A launch's first look at a view was not like its later ones (1.3 to 1.5 % faster on the mobs view, in both surveys), so every launch now warms up over its views before it measures. The helper mod's capture and placement checks pass on all eleven views.
- `optilux calibrate --mode quick|full` runs the null sessions a calibration needs for the current setup (each measures the baseline against two exact copies of itself), announcing how many first and each launch as it starts; a stopped calibration resumes where it left off, and `--recalibrate` makes a fresh one of the same setup when the copies' results drift. It writes the calibration to config/calibrations/: every copy's ratio per view and the thresholds they give, the change a candidate must exceed to count as faster or slower.
- Both modes are calibrated on the bench world, with Complementary Unbound on the played settings as the baseline: across 20 exact copies per mode no view moved by 0.5 % or more, so every threshold sits at its 0.5 % floor. Turning Complementary's shadows off reads 10.7 % faster in quick mode and 12.3 % in full mode, far beyond it, while the session's exact copy reads inside it.
- A measured run that names its calibration is refused unless everything that can move a measurement matches the calibration's. Its record then holds the verdicts: per candidate accept (faster), reject (slower) or inconclusive, over the geometric mean of its views, with each view's change and threshold in % and ms; the copy's own result decides whether the session can be trusted, and a monitor over the last 20 copies says when to recalibrate.
- `optilux compare <run>` re-judges a record against its calibration (or another one) and refuses a record of another setup, naming what differs; `optilux report <run>` writes one static HTML page per run from its record and prints the record's summary: its status, verdicts and items, and how many captures are valid, with each view where one is not.
- The optilux-bench skill for Claude Code runs a run spec the way the sessions above were run: it checks the spec first and reports a refusal with its fix without launching anything, announces the launch, runs the session with the machine left alone, and summarizes the record in `optilux report`'s and `optilux compare`'s own lines. Given a run's name, it summarizes that record.
- `optilux verify records` checks every committed run record against its kind and keeps measurement and calibration records within 200 KB (larger acceptance records from 0.2.0 are reported, never edited); CI runs it, and so does the pre-commit hook whenever a record is staged.

## 0.2.0 Game control
The harness installs the pinned Minecraft, Fabric, mods, Java and tools hash-checked, launches the game directly, and drives it through the rewritten helper mod. Still nothing to run for a shader user: the first real pack arrives in a later release.
- `optilux install` fetches Minecraft 26.3, Fabric Loader 0.19.5, Fabric API, Sodium 0.9.2, Iris 1.11.7, Temurin 25 and PresentMon 2.6.0, each checked against its pinned hash, and checks the launch command against Mojang's and Fabric's metadata.
- `optilux launch <world>` writes the bench display settings (exclusive fullscreen at the desktop's 3840x2160, which `run` requires, vsync off, frame rate unlimited), refuses to start beside a game already running from Optilux's install, a Gradle build or an Optilux trace session, starts the game directly and waits for the world.
- The helper mod, optilux-helper 0.1.0, is a full rewrite. Without the launch's one-time token it stays inert. With it, it serves 17 commands over a local, user-only named pipe: world and state queries, server commands, ticks, exact camera placement, readiness, shader reloads that report compile errors, frame captures with a hashed manifest, input blocking, the HUD, a selftest and quit. `optilux mod build` and `optilux mod test` build it and run its tests.
- `optilux run <spec>` runs an acceptance session and writes a JSON run record, with everything that can move a measurement, under results/records/. The mod's acceptance checks pass on unmodified Complementary Unbound in a provisional world: inert without the token, captures byte-identical to F2 screenshots, exact `/tp` placement, compile errors reported (on a deliberately broken copy), input blocked, frames matched to PresentMon's clock, and the selftest; with a table of memory use over 50 shader reloads.
- The bench world (seed 263) and its eleven views were chosen with the user.
- CI runs the tests, ruff and pyright on Windows, and checks on every pull request the release its merge will create.
- Versions are now MAJOR.MINOR.PATCH, kept in the file VERSION: this release is 0.2.0, each later milestone before 1.0 a minor release (0.3.0 next) and a patch release only for a fix. Releases are titled `Optilux <version>: <name>`.

## 0.00 Foundation
Foundation. Nothing to run yet: no shader pack to install and no benchmark to start.
- Repository: the design, measurement, platform, shader and mod documents, the roadmap and the M0 plan.
- Harness skeleton: the `optilux` command (`test`, `verify docs`, `status`, `milestone start`, `pack build`, `pack release`) with its tests, doc checks and git hooks; CI runs the tests and builds the zip on every push and pull request.
- Release path: every merged milestone creates a private GitHub release carrying optilux-<version>.zip, built the same way on every machine (one tree gives one sha256).
- Placeholder pack: the zip holds a shaders.properties with one comment line and no programs, next to the MIT license and the README with the credit. The first real pack arrives with M3.
